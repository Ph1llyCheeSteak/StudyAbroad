# Hackathon brief

Source: [CPVC AI Hackathon Participant Guide](https://cpvc-ai-hackathon-guide.vercel.app/), reviewed 2026-11-13. The guide says Discord takes precedence if information differs. Times below are Pacific; verify updates with organizers.

## Build and submission

- Build window: Friday November 13, 5:00 p.m. through Sunday November 15, noon. The guide requires a new repo or project started after the window opens, a build created during the window, and preserved project and AI-chat history. Do not delete history, duplicate the project or move to a fresh project at the end. Ask organizers if eligibility or the history of any work is unclear.
- Saturday 2:00 p.m.: submit a project-history link through the form in Discord.
- Saturday 8:00 p.m.: submit the Sunday confirmation and a live link; the guide says this is required for a judging slot.
- Sunday noon: final submission closes. The submitted result is what is judged; the guide says no new features or fixes afterward. Check in at the assigned judging room by 10:00 a.m. and return by 12:55 p.m.
- Submit a live link, project history, description and credits, and a list of AI tools and their uses. An optional demo video under two minutes is required for a challenge entry. Verify the current submission form in Discord.

## Priorities for a few-day build

Prefer one complete, understandable, mobile-friendly student journey over many unfinished features. Prove the main flow works live, collect honest feedback from likely users, identify a specific route to first users and a plausible customer model, and rehearse a four-minute demo. Record meaningful AI use and distinguish working functionality from proposals or mock data.

The guide's rubric awards 25 points each for execution/design and a real problem/user, 20 for a path to customers, and 15 each for pitch/demo and creative AI use. It says the product need not itself be AI, but AI must be used somewhere in the build and disclosed.

## Guardrails

Credit external libraries, templates, APIs and assets; respect their licenses. Do not invent user evidence or collect sensitive data. Use synthetic demo data. The guide forbids mass emails to campus, department or club lists and says to ask the help desk before taking real money. It also says someone outside the team building the project can disqualify a team; confirm uncertain interpretations with organizers. Keep secrets out of public code and demo recordings.
